# 개인 Discord 자료 정리 봇

기존 채널과 메시지를 보존하면서 검색하고, 새 수집함 자료는 내 PC에서 학습한 기준으로 정리합니다. 외부 AI API나 ALT 유료 구독을 사용하지 않습니다.

**현재 상태: 초기 구현본.** 핵심 로직은 로컬 테스트를 거쳤습니다. 이 작업 환경은 패키지 다운로드와 Git 메타데이터 쓰기가 차단되어 있어 실제 Discord 접속·첨부 재업로드·PDF/OCR 엔진·ALT 실시간 수집은 아직 검증하지 못했습니다. 처음에는 별도 테스트 채널과 `delete_inbox = false`로 실행하세요. 봇이 실제로 기록을 읽기 전에는 분류 기준이 학습되어 있지 않습니다.

## 기능

- 기존 허용 채널 전체 읽기 전용 색인. 예전 계정/Deleted User 자료도 포함.
- 한글 키워드 검색, 태그 검색(여러 태그 AND), 승인한 태그 별칭 통합.
- 수집함에 올린 메시지와 첨부파일을 한 자료로 처리.
- 로컬 문자 TF-IDF 기반 학습. 사용자가 확인한 분류만 정답으로 사용.
- 애매한 분류는 분류확인 채널에 대기. 소유자만 분류·태그 수정 및 새 채널 생성 승인.
- 전체 원문을 TXT로 보존하고 첨부파일은 다시 업로드. 업로드 파일의 크기와 SHA-256을 확인.
- 재시작 후 미처리 자료 재개. 게시 결과가 불확실하면 재게시하지 않고 원본 유지.
- ALT 공개 공유 링크의 표시 전사문 추출 시도. 실패 시 TXT 첨부로 대체.

생성형 AI 요약, 그림의 의미 이해, 녹음 자체의 재전사, 무조건 정확한 분류는 제공하지 않습니다. 모델 점수는 유사도이며 정확도 확률이 아닙니다. 초기 자동화는 잠겨 있으며 충분한 확정 표본과 별도 검증을 통과한 분류만 자동 처리합니다.

## 1. 설치 (Windows / Python 3.11 이상)

PowerShell에서 프로젝트 폴더를 열어 실행합니다.

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[documents]"
Copy-Item -LiteralPath config.example.toml -Destination config.toml
```

사진 글자 인식은 별도로 Tesseract와 `kor`, `eng` 언어 데이터를 설치하고 실행 파일을 PATH에 등록해야 합니다. 미설치 상태에서도 봇은 실행되며 사진은 확인 대기로 보냅니다. 로컬 학습·TXT·코드·DOCX 추출은 Python 기본 도구만 사용합니다.

## 2. Discord 봇과 채널 준비

1. [Discord Developer Portal](https://discord.com/developers/applications)에서 애플리케이션과 Bot을 만듭니다.
2. Bot 설정에서 **Message Content Intent**를 켭니다. 일반 사용자 계정 토큰은 사용하지 않습니다.
3. OAuth2 설치 링크에 `bot`, `applications.commands` 범위를 선택해 개인 서버로 초대합니다.
4. 필요한 채널에 View Channels, Read Message History, Send Messages, Attach Files, Embed Links 권한을 줍니다. 새 채널 생성에는 Manage Channels, 수집함 원본 삭제에는 Manage Messages가 필요합니다. Administrator 권한은 필요하지 않습니다.
5. 서버에 수집함과 분류확인용 텍스트 채널을 준비합니다. 기존 보관 채널은 그대로 둡니다.
6. Discord 개발자 모드를 켜고 서버·본인·각 채널의 ID를 복사해 `config.toml`에 입력합니다. 이 파일은 Git 제외입니다.

새 채널은 서버 기본 접근 권한을 상속합니다. 개인 서버 외에서 사용한다면 승인 전에 채널 공개 범위를 확인하세요. 서버·소유자 ID와 허용 채널 목록이 맞지 않으면 관리 명령을 사용할 수 없습니다.

## 3. 실행

```powershell
.\scripts\start.ps1 -Check
.\scripts\start.ps1
```

숨김 입력창 붙여넣기가 동작하지 않으면 ` .\scripts\start.ps1 -ClipboardToken`을 실행하세요. 안내가 나온 **다음에** Discord에서 토큰만 복사하고, PowerShell로 돌아와 붙여넣기 없이 Enter만 누릅니다. 복사한 명령어가 토큰을 덮어쓰는 혼선을 피하고 클립보드 값을 로컬 환경 변수로 직접 읽습니다. 토큰은 화면에 출력하지 않습니다.

클립보드 연동도 동작하지 않으면 메모장에 토큰만 한 줄로 저장한 뒤 `.\scripts\start.ps1 -TokenFile .\data\bot-token.txt`로 읽을 수 있습니다. `data/`는 Git 제외 폴더입니다. 이 파일은 토큰을 평문으로 저장하므로 다른 사람과 공유하지 마세요. 프로그램은 값을 출력하지 않으며 실행 종료 시 환경 변수를 제거합니다. 파일은 사용자가 삭제할 때까지 남습니다.

실행 스크립트가 토큰을 가려서 입력받습니다. 토큰은 로컬 환경 변수에만 넣고 종료 시 제거합니다. **토큰을 채팅이나 Git에 올리지 마세요.** `.env.example`은 설명용이며 자동 로딩하지 않습니다.

PowerShell 정책 때문에 스크립트 실행이 막히면 시스템 정책을 변경하지 않고 다음처럼 실행할 수 있습니다.

```powershell
$env:PYTHONPATH = 'src'
$secret = Read-Host 'Bot token' -AsSecureString
$env:DISCORD_BOT_TOKEN = [System.Net.NetworkCredential]::new('', $secret).Password
.\.venv\Scripts\python.exe -m discord_archive.app
Remove-Item Env:DISCORD_BOT_TOKEN
```

PC 인터넷 연결과 프로그램 실행이 필요합니다. 절전 중에는 처리되지 않고 다음 실행 때 재개합니다. Discord 앱을 열어둘 필요는 없습니다. 같은 데이터 폴더에서는 봇을 하나만 실행할 수 있습니다.

## 4. 처음 사용할 때

첫 접속 시 허용 채널 전체를 오래된 글부터 읽고 색인합니다. 원문은 옮기거나 삭제하지 않습니다. 파일이 많으면 시간이 걸리고, 설정된 로컬 저장공간을 사용합니다. 기본 파일 상한은 25 MiB, 전체 저장 상한은 5 GiB이며 실제 Discord 업로드 한도가 더 낮으면 그 한도를 적용합니다. 초과 자료는 원본 유지/확인 대기로 처리합니다.

1. `/검색 최소자승법` 등으로 기존 자료를 찾아 자료 ID를 확인합니다.
2. `/기준`에 자료 ID, 정답 채널, 쉼표로 나눈 태그를 넣습니다. 기존 자료는 이동하지 않습니다.
3. 분류별로 서로 다른 예시를 확인합니다. 현재 채널은 초기 추천 단서이고 확정 정답이 아닙니다.
4. 수집함에 간단한 글과 작은 파일을 넣고 분류확인의 채널 선택 → 태그 수정 → 보관 승인 흐름을 시험합니다.
5. 보관된 원문/파일을 직접 확인한 뒤, 오려두기를 원하면 봇 종료 후 `config.toml`의 `delete_inbox = true`로 바꾸고 다시 실행합니다.

자동 분류에는 기본적으로 채널별 검증 예시 20개 이상, 검증 예측 20개 이상, 검증 정밀도 95% 이상, 새 자료 유사도 0.90 이상과 차순위와의 차이 0.15 이상을 요구합니다. 중복 내용은 예시 수를 늘리지 않습니다. 자료가 적으면 계속 확인 대기로 처리되는 것이 정상입니다.

## 명령

| 명령 | 용도 |
|---|---|
| `/검색` | 제목·본문·추출 텍스트 키워드 검색, 페이지 지정 |
| `/태그` | `Python, 수학`처럼 입력하여 모든 태그가 있는 자료 검색 |
| `/기준` | 기존 자료의 정답 분류·태그 확정, 자동 재학습 |
| `/태그별칭` | `파이썬` → `Python`처럼 대표 태그 지정 |
| `/색인` | 기존 허용 채널의 새 기록 색인 |
| `/학습` | 확정 예시로 다시 학습 |
| `/상태` | 작업 상태와 대기 사유 보기 |
| `/재수집` | 추출 실패·수정된 수집함 자료를 다시 분석 |
| `/재시도` | 불확실한 보관 작업을 **재게시 없이** 검색·재검증 |
| `/백업` | 로컬 DB와 확정 기준 백업 |

분류확인 버튼은 재시작 후에도 기존 작업 ID로 연결됩니다. 태그를 바꾼 뒤 보관 승인을 눌러야 정답 예시로 확정됩니다. 새 채널 버튼은 이름을 입력해 제출하면 채널 생성과 해당 자료 보관을 승인하는 동작입니다.

## 지원 자료

| 종류 | 처리 |
|---|---|
| TXT, Markdown, 코드, JSON 등 | 텍스트와 파일명 분석, 원본 보존 |
| DOCX | 본문·표의 텍스트 추출 |
| 텍스트 PDF | 선택 pypdf 엔진, 최대 500페이지 |
| 사진 | 선택 로컬 OCR, 내용 없는 사진은 확인 대기 |
| 스캔/혼합 PDF | 추출 가능한 글은 검색에 사용, OCR 텍스트 첨부 필요 표시 |
| HWP/HWPX/DOC, 기타 문서 | 현재 내용 추출 미지원, 원본 파일과 메모로 수동 분류 가능 |
| 강의 녹음 | 재전사하지 않음. ALT 전사문이나 메모를 별도 자료로 추가 |

미지원 파일도 보관할 수 있으나, 다운로드·재업로드 한도를 넘는 파일은 보관 완료로 처리하지 않습니다. 원본과 정리본은 봇 게시 시 작성자가 달라집니다. 실제 원작성자 ID와 날짜는 보관 TXT에 남습니다. 수집함 원본을 삭제하면 원본 메시지 링크는 더 이상 열리지 않을 수 있으며 검색은 새 보관 글로 연결합니다.

## ALT (iPad)

ALT에서 공유 링크 생성 → Discord 수집함에 링크 붙여넣기. 봇이 공개 페이지에서 시간 표시가 있는 전사문을 읽으면 전체 내용을 보관 TXT에 포함합니다. 공유하지 않은 ALT 노트 전체를 자동 탐색하지 않습니다. ALT 유료 API는 사용하지 않습니다.

웹 페이지가 JavaScript 렌더링만 제공하거나 공유가 해제되면 자동 수집이 실패할 수 있습니다. 현재 자동 추출은 실시간 검증 전입니다. 이때 링크를 유지하고 TXT로 내보내 수집함에 첨부하세요. 동일 노트 ID는 중복 경고하며 명시적인 `/재수집`에서만 같은 자료를 다시 분석합니다. 사이트 변경이나 접근 제한을 우회하지 않습니다.

## 대기·오류 복구

- **지원하지 않는 문서/추출 실패:** 내용을 텍스트로 첨부하거나 태그/목적지를 직접 확인합니다.
- **크기/저장 상한:** 원본이 유지됩니다. 공간이나 설정을 조정한 뒤 `/재수집`합니다.
- **게시 결과 불확실:** `/재시도`는 해당 작업 마커를 찾아 완전한 정리본이 있는지만 검증합니다. 일부만 게시됐다면 자동 재게시·원본 삭제를 하지 않습니다. 목적지의 부분 게시글과 원본을 직접 확인해야 합니다.
- **삭제 권한 없음/원문 수정됨:** 보관본을 검증하더라도 수집함 원본이 남고 작업 상태에 이유가 표시됩니다.
- **분류확인 안내글을 지웠을 때:** 자료와 작업은 DB에 남습니다. 원본을 지우지 말고 복구 점검을 요청하세요.

## 백업과 복원

`/백업`은 SQLite backup API로 `data/backups`에 DB 사본을 만듭니다. DB에는 검색 텍스트, 작업 상태, 정답 예시, 태그가 들어 있습니다. **첨부파일과 모델 파일은 별도이므로**, 봇을 종료한 상태에서 `data` 폴더 전체와 `config.toml`을 안전한 곳에 복사하는 방법을 권장합니다. Discord 자체가 별도 백업은 아닙니다.

복원은 봇을 종료하고 현재 폴더를 따로 보존한 뒤 `data`와 설정을 되돌립니다. DB만 복원할 경우 `archive.sqlite`를 백업본으로 교체하고 이전 `-wal`/`-shm` 파일을 함께 섞지 마세요. 파일이 빠진 작업은 검증 실패로 원본 삭제를 멈춥니다. 모델은 `/학습`으로 DB의 확정 예시에서 재생성할 수 있습니다.

## 개발 검증

```powershell
$env:PYTHONPATH = 'src'
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m compileall -q src
.\.venv\Scripts\python.exe -m discord_archive.app --check --config config.example.toml
```

테스트는 합성 자료와 SQLite를 사용하며 실제 Discord 메시지를 수정하지 않습니다. 선택 엔진이 없는 환경에서는 미설치/실패 대기 동작만 검증합니다. 라이브 서버 검증 완료 전에는 자동 삭제를 켜지 마세요.

설계와 구현 계획은 `docs/superpowers/`에 있습니다. 배포 전 실제 서버에서 권한, 최초 전체 색인, 확인 UI, 첨부 해시 검증, 중단 후 재개를 시험해야 합니다.
