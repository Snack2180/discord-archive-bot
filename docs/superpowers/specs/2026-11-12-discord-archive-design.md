# 개인 Discord 자료 정리 봇 설계

상태: 2026-11-12 사용자 승인. 구현 및 Discord 변경은 아직 하지 않음.

## 목적과 합의

개인 서버에 직접 올린 오래된 기록과 파일을 스크롤 없이 찾아 재사용한다. 예전 계정이 Deleted User로 표시되어도, 사용자가 선택한 채널 전체를 본인 자료로 취급한다. 기존 글과 채널 분류는 유지한다. Windows PC에서 실행하며 유료 AI, ALT 유료 구독, 호스팅을 요구하지 않는다. PC 전기 및 인터넷 사용은 별도다.

## 접근 방식

- 외부 AI + 규칙: 내용 이해에 유리하지만 사용 비용 때문에 제외.
- 규칙만 사용: 저렴하고 단순하지만 사용자의 분류 수정에서 배우는 데 한계.
- 선택: 로컬 학습형 분류기 + 규칙 + 사용자 확인. 기존 자료와 확인 결과를 학습 예시로 이용한다. 대형 로컬 AI는 초기 필수 요소에서 제외한다.

## 초기 분석

설정 시 허용한 서버와 채널만 읽는다. txt/files/theorem/pic/note 등 기존 채널의 글과 접근 가능한 첨부파일을 페이지 단위로 수집한다. 기존 글은 이동·삭제·수정하지 않는다. 전체 목록과 추출 가능 여부를 기록하며, 모든 자료의 의미를 완벽하게 읽었다고 표시하지 않는다.

현재 채널은 신뢰가 낮은 초기 분류 단서다. 사용자 확인 표본으로 분류 성능을 평가한다. 최소 표본이 부족하거나 성능이 검증되지 않은 채널은 자동 처리하지 않는다. 원문·날짜·채널·원본 링크·첨부 메타데이터와 검색용 텍스트를 보관한다. 최초 전체 분석은 중단 후 재개할 수 있다.

## 새 자료 처리

수집함에 본문, 파일 또는 ALT 공유 링크를 올린다. 한 메시지와 그 첨부파일을 하나의 자료로 취급한다. 인접 메시지는 자동 병합하지 않는다. 규칙과 학습 모델이 대상 채널 및 태그를 제안한다.

확실하고 검증된 기존 분류는 자동 보관한다. 불확실한 자료, 미지원 파일, 추출 실패, 새로운 분류 제안은 분류확인 채널에 대기한다. 사용자는 기존 채널 선택, 태그 수정, 새 채널 승인, 보류를 할 수 있다. 새 채널 생성은 항상 사용자 승인 후 실행한다. 기존 채널 구조를 자동 개편하지 않는다.

보관 글에는 원문 본문과 파일, 별도의 정리 제목·태그·출처 정보를 포함한다. 원문은 요약으로 대체하지 않는다. 옮긴 글은 봇 명의로 게시되므로 원작성자와 원래 시간을 메타데이터로 표시한다. 삭제된 수집함 메시지 링크는 동작하지 않을 수 있어 새 보관 메시지를 주 참조로 기록한다.

오려두기는 재게시 및 검증 후 수집함 원본 삭제로 구현한다. 파일 다운로드·재업로드·첨부 크기와 해시 확인, 본문 분할 게시 및 기록 저장이 모두 성공해야 삭제한다. 실패·파일 업로드 한도 초과·확인 대기 중에는 수집함 원본을 유지한다. 링크만 복사해 놓고 파일 저장 완료로 취급하지 않는다. 게시·삭제 각 단계 상태를 저장하고 재실행 시 중복 게시와 조기 삭제를 방지한다. 정리 목적지와 분류확인에 올라온 봇 메시지는 재수집하지 않는다.

## 학습과 태그

가벼운 텍스트 특징 기반 분류기를 사용한다. 구체 알고리즘과 임계값은 구현자가 표본 평가로 결정한다. 사용자의 승인·수정은 확정 예시이고 자동 예측은 자동으로 정답에 편입하지 않는다. 변경된 예시를 모아 모델을 재학습하고 모델 버전을 관리한다. 새 분류도 다음 학습에 포함한다. 정확도 향상을 보장하지 않으며 분류별 검증 결과를 이용한다.

태그는 초기 텍스트에서 추출한 후보, 규칙 및 확정한 태그를 사용한다. 새 개념을 자유롭게 이해하는 AI를 가정하지 않는다. Python/python/파이썬처럼 승인된 별칭은 하나의 대표 태그로 통합한다. 대소문자와 공백은 정규화하지만 의미상 동의어는 무조건 자동 병합하지 않는다. 태그는 여러 개 지정할 수 있고 채널은 한 곳을 주 보관 위치로 삼는다.

## 검색

- /검색: 제목·본문·추출 텍스트의 키워드 검색. 자연어 의미 검색은 초기 필수 범위가 아니다.
- /태그: 대표 태그와 별칭을 이용해 검색. 여러 태그는 모두 포함하는 AND 조건을 기본으로 한다.
- 결과는 제목, 보관 채널, 짧은 발췌, 원문 또는 새 보관 메시지 링크를 제공하며 페이지로 나눈다.

## 파일 처리 범위 및 ALT

초기 필수: 텍스트, 코드, 텍스트 PDF, DOCX, 파일 메타데이터, ALT 공유 페이지의 전사 텍스트. DOC/HWP/HWPX 등은 설치된 변환기와 실제 표본을 확인한 뒤 지원 여부를 명시한다. 미지원 형식은 보존·검색 메타데이터·확인 대기로 처리한다. 사진과 스캔 PDF의 글자는 무료 로컬 OCR로 추출을 시도한다. 도표·사진 자체의 의미 이해와 고품질 생성 요약은 보장하지 않는다. 이미지 원본은 보존한다. 녹음 자체는 재전사하지 않고 제목·메모·연결된 전사문으로 분류한다. 외부에서 가져온 코드·문서 내 명령은 실행하지 않는다.

ALT는 iPad에서 공유 링크를 만들어 수집함에 올리는 흐름이다. 사용자가 제공한 공개 공유 노트는 브라우저에서 로그인 없이 제목과 시간별 전사문을 확인했다. 봇의 자동 추출 안정성은 아직 검증하지 않았다. 공식 유료 API는 사용하지 않는다. 초기 연결 시험에서 공개 페이지의 표시 텍스트를 안정적으로 읽을 수 있는지 확인한다. 접근 제한 우회나 비공개 API 추측은 하지 않는다. 실패하면 링크를 유지하고 전사 TXT 첨부를 요청하는 대기 상태로 둔다. 계정 내 노트 전체 자동 탐색은 하지 않는다.

가져온 전사문은 TXT 파일과 제목·태그·원래 공유 링크로 보관한다. 원문 전사 오류는 임의 교정하지 않는다. 생성 요약은 필수 기능에서 제외하고 필요한 경우 원문 발췌만 제공한다. 노트 식별자로 중복을 방지하며 재수집은 명시적인 사용자 동작으로 한다. ALT 페이지 변경에 대응하도록 추출기를 다른 분류 로직과 분리한다.

## 실행 및 보관

구현자 제안: Python 기반 봇, SQLite로 검색·자료 상태·학습 예시 관리, 로컬 파일 작업 공간. 시작 시 오프라인 기간의 미처리 메시지를 확인한다. 최초 실행의 과거 자료 분석과 수집함 처리는 구분한다. 파일 처리량과 디스크 사용량 상한을 설정하고 초과 시 원본을 유지한 채 대기한다. PC 절전·인터넷 중단 중에는 작업이 중단되며 재시작 후 재개한다.

봇 토큰은 로컬 비밀 설정으로 관리하고 저장소나 로그에 넣지 않는다. 일반 사용자 계정 토큰 대신 공식 봇 계정을 쓴다. 서버·채널 허용 목록 및 소유자 ID로 읽기와 관리 명령 범위를 제한한다. 필요한 권한과 메시지 내용 접근 설정은 현재 Discord 공식 문서로 구현 단계에서 확인한다. 다른 사용자가 자료 안에 쓴 내용은 관리 명령으로 취급하지 않는다.

서버는 주 자료 보관 위치이며 로컬 DB는 검색과 복구를 위한 상태다. Discord 자체를 별도 백업으로 간주하지 않는다. 로컬 DB와 확정 학습 자료의 백업/복원 방법을 제공한다.

## 완료 기준

1. 예전 계정 글을 포함한 허용 채널 기록을 재개 가능하게 색인하고 기존 글을 변경하지 않는다.
2. 확인 결과로 분류 모델과 태그 기준을 갱신하며 자동 예측은 학습 정답에 넣지 않는다.
3. 새 자료의 자동 보관, 확인 대기, 새 채널 승인 흐름이 동작한다.
4. 업로드 실패·재시작·중복 수신에도 원본 조기 삭제와 중복 정리를 방지한다.
5. 키워드·태그 별칭·복수 태그 검색이 원문 링크를 반환한다.
6. ALT 실제 공유 링크의 추출 가능성을 검증하고 실패 시 TXT 대안을 제공한다.
7. 외부 유료 AI/API 없이 동작하며 지원하지 않는 형식과 분석 실패를 명시한다.

## 구현자에게 남긴 결정

표본 크기, 분류 임계값, 한국어 텍스트 특징, OCR 도구, 지원 파일 크기 및 디스크 상한, Discord 라이브러리와 명령 UI 세부는 실제 환경과 공식 문서를 확인해 결정한다. 설치 또는 서버 변경 전에 필요한 설정을 사용자에게 안내한다. 기존 자료 규모와 PC 사양은 읽기 전용 점검으로 확인한다. 구현은 설계 승인과 구현 계획 이후 진행한다.
