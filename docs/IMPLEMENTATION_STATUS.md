## 설계 대비 결정 및 영향

1. Git 메타데이터 쓰기가 차단되어 현재 작업 폴더에서 작업했다. 커밋/원격 업로드는 미완료이며 로컬 파일과 이 기록을 보존한다.
2. Git 기반 실행 보조 스크립트 대신 파일 원장과 실제 테스트 실행으로 단계를 기록했다. 커밋 단위 추적이 아직 불가능하다.
3. 패키지 다운로드가 네트워크 프록시에서 거부되어 기본 unittest를 사용했다. 외부 의존성이 필요한 어댑터는 컴파일 확인만 했으며 실제 설치 후 검증해야 한다.
4. scikit-learn 로지스틱 분류 대신 Python 기본 도구의 문자 TF-IDF 중심점 분류를 구현했다. 검증 정밀도와 유사도 기준을 보수적으로 적용하며 실제 사용자 자료에서 정확도는 미측정이다.
5. 스캔 PDF 자동 OCR은 첫 버전에서 확인/TXT 대안으로 처리한다. 사진 OCR 어댑터는 있으나 엔진 미설치로 성공 경로 미검증이다.
6. 기록 색인은 오래된 글부터 마지막 처리 ID 이후를 읽도록 구현했다. 재시작 시 중복을 피하고 새 글을 추가한다. 과거 글 수정 자동 동기화는 제공하지 않는다.
7. GitHub 저장소는 사용자가 직접 생성했고, 이후 공개 저장소 사용과 코드 업로드를 승인했다. 개인 자료·실제 설정·봇 토큰은 업로드 대상에서 제외한다. 원격 반영 내역은 저장소 커밋 기록으로 확인한다.
8. 수집함 자동 삭제는 초기 실서버 검증을 위해 기본값을 false로 둔다. 검증 후 사용자가 true로 설정하면 승인된 오려두기가 활성화된다.

## 남은 실제 환경 확인

- Discord 봇 토큰 생성, 서버 초대, Message Content Intent와 채널 권한 설정.
- discord.py 설치 후 명령 등록, 확인 UI, 새 채널 승인 생성, 최초 색인 확인.
- 작은 테스트 파일로 업로드·해시 확인·원문 삭제·중단 후 복구 시험.
- pypdf/로컬 OCR 설치 후 실제 PDF·사진 표본 확인.
- ALT 공개 공유 페이지 수집 가능성. 실제 요청은 현재 환경에서 네트워크 연결이 거부됐으므로 성공이라고 보고하지 않는다. 실패 시 원본 유지 및 TXT 대안.
- 실제 자료의 분류별 검증 성능 확인. 예시가 부족하면 수동 확인이 계속된다.
